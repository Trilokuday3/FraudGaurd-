# Data Dictionary — Sub-project 1 (Data Foundation)

Generated by `generator/generate.py`. Source of truth for allowed values is
`libs/fraudguard_core/src/fraudguard_core/enums.py`; schemas that enforce this
table are in `libs/fraudguard_core/src/fraudguard_core/schemas.py`.

## `customers.parquet`
| column | type | description |
|---|---|---|
| customer_id | string | PK, `CUST%07d` |
| account_created_at | timestamp | account open time |
| customer_segment | category | `retail` / `premium` / `business` |
| home_country | category | 2-letter code, one of `enums.COUNTRIES` |
| home_city | string | drawn from `enums.CITIES_BY_COUNTRY[home_country]` |

## `merchants.parquet`
| column | type | description |
|---|---|---|
| merchant_id | string | PK, `MERC%06d` |
| merchant_category | category | `grocery` / `electronics` / `travel` / `gaming` / `crypto` / `fashion` / `dining` / `other` |
| country | category | merchant's registered country |
| created_at | timestamp | merchant onboarding date |

**Deliberately absent:** `base_fraud_rate` — a generator-internal latent
variable driving label generation. Never serialized. A real merchant-risk
feature must be *estimated* from historical labeled transactions in
sub-project 2, not read off this table — see leakage guards below.

## `devices.parquet`
| column | type | description |
|---|---|---|
| device_id | string | PK, `DEV%07d` |
| customer_id | string | FK → `customers.customer_id`; a device belongs to exactly one customer in v1 |
| device_type | category | `mobile` / `desktop` / `tablet` |
| first_seen_at | timestamp | first transaction that used this device |

## `transactions.parquet`
| column | type | description |
|---|---|---|
| transaction_id | string | PK, `TXN%010d` |
| customer_id | string | FK → `customers.customer_id` |
| merchant_id | string | FK → `merchants.merchant_id` |
| device_id | string | FK → `devices.device_id`, always owned by the same `customer_id` |
| timestamp | timestamp | transaction time |
| amount | float | > 0, lognormal by `customer_segment` |
| currency | category | `USD` / `GBP` / `INR` / `EUR`, derived from `country` |
| payment_method | category | `card` / `wallet` / `bank_transfer` |
| country | category | transaction country; usually `home_country`, ~3% cross-border |
| city | string | city within `country` |
| ip_country | category | usually `country`; ~2% mismatch (proxy/VPN signal) |

**Deliberately absent:** any fraud/outcome column. See `ground_truth.parquet`.

## `ground_truth.parquet` — kept separate, never joined into feature-building code
| column | type | description |
|---|---|---|
| transaction_id | string | FK → `transactions.transaction_id`, 1:1 |
| fraud_probability_true | float | the latent model's true P(fraud), in [0,1] — usable to check calibration in sub-project 3, never as a feature |
| fraud_label | int (0/1) | **the target** |
| confirmed_fraud_at | timestamp, nullable | non-null iff `fraud_label=1`; 0–14 days after `timestamp`, models real-world label delay |

## Leakage guards (enforced by `tests/dq/test_dq_suite.py::test_no_forbidden_leakage_columns`)

- `merchants.parquet` never has a `base_fraud_rate` (or similar) column.
- `transactions.parquet` never has `fraud_label`, `fraud_probability_true`, or
  `confirmed_fraud_at`.
- Any feature that wants a merchant-risk or customer-risk signal must compute
  it from **historical `ground_truth` joined only up to the point in time of
  the transaction being scored** — exactly how a real system would have to
  learn merchant risk from confirmed fraud history, not from a hidden oracle
  column. This is the same discipline `amount_ratio` and `velocity_1h` follow
  inside the generator itself (see `docs/data-generation-model.md`).
